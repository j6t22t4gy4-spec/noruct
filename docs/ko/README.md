## Noruct가 하려는 일

사용자가 목표를 주면 관련 자료를 찾고, 필요한 작업을 나누고, 허용된 행동을 실행한 뒤 결과를 확인하는 시스템을 설계합니다. 업무가 끝나면 검증된 절차와 필요한 기록은 남기되, 그때의 임시 계획을 다음 업무의 권한으로 취급하지 않습니다.

예를 들어 입고가 늦어진 자재가 어떤 주문에 영향을 주는지 확인할 때, 재고 조회만 필요하면 한 번의 처리로 끝냅니다. 생산계획과 주문이 충돌하면 확인 작업을 나누되 결과를 다시 맞춥니다. 납기 변경은 조회와 다른 권한으로 검사합니다. 이 사례는 목표 동작을 설명하며 현장 성능을 입증한 결과가 아닙니다.

<a id="terms"></a>
## 공통 용어

본문에서는 기능을 설명하는 한국어를 우선 사용합니다. 아래 구현 이름은 상세 설계와 코드를 대조할 때만 필요합니다. 같은 이름이 등장해도 목표 설계와 실제 구현은 구분해서 읽습니다.

| 읽기 쉬운 표현 | 구현·설계 이름 | 뜻 |
| --- | --- | --- |
| 회사의 업무 규칙 | `Company` | 여러 업무에 걸쳐 유지되는 목표·권한·예산의 범위. 실제 법인을 뜻하지 않습니다. |
| 개별 업무 | `Job` | 완료 조건이 있는 하나의 과업. 실행이 끊겨도 업무 자체는 남을 수 있습니다. |
| 재사용 가능한 수행 단위 | `Employee` | 승인된 도구·절차·제한된 기억을 가진 단위. 사람의 고용관계를 뜻하지 않습니다. |
| 실행 시도 | `EmployeeRun` | 수행 단위가 맡은 업무를 실제로 처리하는 한 차례 실행. |
| 작업 조율과 행동 제안 | `Manager` | 업무를 나누고 다음 행동을 제안합니다. 제안 자체가 실행 허가는 아닙니다. |
| 실행 허용 규칙의 검사 | `Kernel` | 정해진 권한과 현재 업무 상태에 따라 실행 가능 여부를 검사합니다. |
| 업무 지시와 완료 기준 | `Work Order` | 요청의 목표, 범위, 제약과 완료 기준을 명시합니다. |
| 작업 의존관계 | `Graph` | 작업의 선후관계, 결과 전달, 병렬 가능성을 나타냅니다. |
| 재사용할 실행 설계안 | `Blueprint` | 다음 작업에서 검토할 설계안이며 저장만으로 실행 권한이 생기지 않습니다. |
| 재사용 절차 | `Skill` | 도구 사용이나 검사를 수행하는 버전 관리 절차입니다. |
| 검토할 변경안 | `Patch` | 현재 규칙이나 절차를 바꾸기 위한 제안이며 검토·적용과 구분됩니다. |
| 실행 기록 | `Receipt` | 무엇을 실행했고 어떤 결과를 관찰했는지 남깁니다. 기록 존재만으로 성공은 아닙니다. |
| 결과 판정 기준 | `Oracle` | 성공 여부를 검사할 기준이나 외부 결과입니다. 무조건 옳은 AI를 뜻하지 않습니다. |
| 근거 요약 | `Evidence Brief` | 출처·최신성·불확실성을 포함한 과업 관련 자료 요약입니다. |
| 모델 제공사와 선택 경로 | `Provider / route` | 사용할 서비스·모델·실행 설정의 조합. 자료 전송 허용 여부를 별도로 확인합니다. |
| 선택한 버전 고정 | `Pin` | 검토한 정확한 버전을 사용하도록 고정합니다. 업데이트와 재승인은 별도입니다. |
| 변경 확정 | `Commit` | 제안을 공식 결과나 실제 시스템에 반영하는 일. Git 작업만을 뜻하지 않습니다. |
| 입출력과 책임의 약속 | `Contract` | 필요한 입력, 허용 행동, 결과 형식과 책임을 정한 규칙. 법적 계약 여부와는 구분합니다. |

## 공개 문서의 경계

이 문서는 제품 방향과 사용자에게 약속하는 동작 원칙을 설명합니다. source intake, runtime implementation,
보안 운영 세부, 벤치마크, 고객 데이터와 개발 이력은 포함하지 않습니다.

영문판과 번역판의 표현이 다를 경우 영문판이 정본입니다.

[개발 범위와 비주장](08-current-development-status.md)은 비주장을 설명하며 최신 구현 현황표가 아닙니다.
01·10에는 개발 진술이 포함되어 있지만 이 공개 묶음은 그 바탕인 비공개 평가 기록을 제공하지 않습니다.
개념·설계에 등장한다고 해서 해당 기능의 일반 제공이나 상용 검증이 입증되는 것은 아닙니다.
